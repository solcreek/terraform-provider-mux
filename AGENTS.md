# Contributor instructions

- Write all repository documentation, comments, examples, and diagnostics in US English.
- License original source under MPL-2.0. Preserve dependency licenses and notices, and review license compatibility before adding code or dependencies.
- Keep the Mux API client (`internal/mux`) standard-library only. Mux publishes an official Go SDK (`muxinc/mux-go`, MIT); it is deliberately not used: it is generated, lags the API (no webhooks or whoami as of 2026-11-16), and the provider needs to own retries, rate limiting and error messages. Implement against Mux's [API reference](https://www.mux.com/docs/api-reference) and OpenAPI specification (`https://www.mux.com/api-spec.json`); where the live API differs from them, follow the live API and say so in a dated comment. Do not vendor the specification or generate code from it.
- Manage configuration, not content. Playback restrictions, signing keys, webhooks, long-lived live streams and what hangs off them belong here; assets, uploads and anything an application creates at run time do not.
- An object whose ID or secret is stored elsewhere must never be replaced to apply a change that an update endpoint can make. `mux_playback_restriction` changes only through its two in-place endpoints. Where Mux offers no update (playback IDs, simulcast targets, a live stream's `audio_only`), say so in the attribute description.
- Follow Terraform Plugin Framework plan/state consistency, import, and diagnostic conventions. Every resource needs a lifecycle test against the in-memory fake API (`internal/provider/fake_mux_test.go`), and the fake must keep mirroring observed live behavior: when `TestAccAPIFacts` shows a difference, change the fake and its dated comment. Mux leaves unset and false fields out of its responses; model that in the fake, because it is where null-versus-empty bugs come from.
- Destructive operations stay guarded: playback restrictions, signing keys and live streams keep `deletion_protection = true` by default. A resource must never adopt something it did not create: refuse and point to `terraform import`.
- Never expose credentials in diagnostics, logs, example files, or URLs. Mark secrets `Sensitive`; they still persist in state. Test fixtures and examples use made-up IDs and `example.com` domains, never values from a real environment.
- Keep commits atomic and commit completed, verified work frequently. Run `make test` (and `make test-tofu`) before each code commit, and `make generate` when schema, examples or templates change. Configuration syntax in examples and tests must work on Terraform 1.5.7, the latest Terraform and the latest OpenTofu.
- Do not claim live Mux verification from local fixtures. Real API tests require explicit opt-in (`TF_ACC`, `MUX_TOKEN_ID`, `MUX_TOKEN_SECRET`) and refuse a token that does not belong to a `development` environment. They create and delete objects marked `tf-acc-*` and never touch anything else. Mux rate limits writes to about one per second: do not probe the API in a tight loop.
- Follow the Solcreek Gandi provider's OpenTofu Registry release layout. Preserve published version tags and the registered Solcreek signing identity.
